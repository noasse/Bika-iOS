# 图片加载诊断日志与导出设计

## 状态

已于 2026-07-25 经用户确认。

## 背景

阅读器与漫画封面偶发显示空白。现有图片管线会在网络、缓存或解码失败后停止加载动画，但缺少可导出的运行时证据，无法准确区分以下情况：

- 图片地址错误或服务器返回非成功状态；
- 服务器以成功状态返回 HTML 等非图片内容；
- 响应内容被截断，图片头可读取但像素无法解码；
- URLCache 或解码缓存命中错误内容；
- 可见图片请求与阅读器预加载共享、取消或重试；
- 图片已经成功解码，但没有交给最终视图显示。

本功能为 iOS App 增加默认常开的图片加载诊断日志，并允许用户从设置页一键导出。

## 目标

- 记录封面、阅读器当前页和阅读器预加载的完整图片加载时间线。
- App 重启后仍保留最近 2,000 条事件，超过上限自动覆盖最旧事件。
- 从设置页导出单个结构化 JSON 文件，便于人工检查和程序分析。
- 记录完整图片 URL，以便精确定位失败资源。
- 从采集阶段排除 Token、Cookie、密码和其他账号凭据。
- 日志系统发生任何错误时，不得阻塞或改变图片加载结果。
- 不改变阅读器真实高度计算、横竖阅读布局和封面展示规则。

## 非目标

- 不建立通用的全 App 行为分析系统。
- 不记录登录、收藏、评论、搜索等普通业务操作。
- 不记录图片二进制内容、Authorization 请求头、Cookie 或用户密码。
- 不上传日志到服务器；只有用户主动导出并分享时，文件才离开 App 沙盒。
- 不提供无限期日志归档或可配置的保留数量。

## 方案选择

采用“App 自有结构化环形日志 + OSLog 关键事件”：

- App 自有日志保证可稳定读取、测试和导出；
- OSLog 只镜像关键错误，方便连接 Xcode 时实时查看；
- 不依赖 OSLogStore 导出历史系统日志，因为普通 App 对系统日志读取存在限制；
- 不使用纯内存日志，因为 App 重启或异常退出后证据会丢失。

## 架构

### ImageDiagnosticsStore

新增独立的图片诊断存储组件，负责：

- 接收结构化 `ImageDiagnosticEvent`；
- 在独立串行执行上下文中写入文件；
- 保留最近 2,000 条事件；
- 提供当前条数和最近一次错误时间；
- 生成一致的只读快照；
- 清空全部日志；
- 将关键错误同步镜像到 OSLog。

图片缓存、网络、解码和显示组件只提交事件，不直接操作日志文件。

日志存放在 App 的 Caches 目录。该数据允许被系统在存储紧张时清理；日志缺失不能影响 App 功能。

### ImageDiagnosticEvent

每条事件至少包含：

- `timestamp`：UTC 时间；
- `requestID`：一次调用方图片加载的 UUID；
- `networkRequestID`：实际网络请求的 UUID；共享请求的多个调用方使用同一个值；
- `sequence`：保证同一快照内稳定排序的递增序号；
- `purpose`：`cover`、`readerVisible`、`readerPrefetch` 或 `unspecified`；
- `stage`：调用、内存缓存、响应缓存、网络、解码、显示；
- `action`：开始、命中、未命中、加入共享请求、响应、重试、驱逐、成功、失败或取消；
- `url`：完整图片 URL；
- `cacheIdentity`：包含 URL、解码目标和 overscan 的缓存标识；
- `httpStatus`：存在 HTTP 响应时记录；
- `responseBytes`：响应字节数；
- `durationMilliseconds`：当前阶段耗时；
- `retryAttempt`：从 0 开始的尝试序号；
- `decodeTarget`：full、fit、fill 或 fitWidth 及其尺寸；
- `sourcePixelSize` 与 `decodedPixelSize`：能够获得时记录；
- `errorDomain`、`errorCode` 和安全的错误描述；
- `metadata`：仅允许预定义、非敏感的补充字段。

事件模型使用 `Codable` 和 `Sendable`，禁止接收任意请求头或任意字典作为输入，避免调用方误写敏感信息。

### 诊断上下文

新增轻量的 `ImageDiagnosticContext`，由调用方创建并沿图片管线传递，包含：

- `requestID`；
- `purpose`；
- 完整 URL；
- 可选页面稳定标识，但不包含漫画标题、账号或个人信息。

封面组件标记 `cover`，可见阅读页标记 `readerVisible`，阅读器相邻图片预加载标记 `readerPrefetch`。

当多个调用方共享同一缓存或网络任务时：

- 每个调用方保留自己的 `requestID`；
- 实际底层任务分配一个 `networkRequestID`；
- 后加入的调用方记录“加入共享请求”；
- 底层请求结果记录一次，并可通过 `networkRequestID` 与各调用方关联。

## 数据流

一次正常加载的典型时间线：

1. 调用方记录 `load/start`。
2. ImageCache 记录解码内存缓存命中或未命中。
3. URLSessionImageDataLoader 记录响应缓存命中、未命中或无效缓存驱逐。
4. 发起网络请求并记录 `network/start`。
5. 收到响应后记录状态码、字节数和耗时。
6. 临时错误发生时记录失败原因和下一次重试序号。
7. ImageDecoding 记录目标尺寸、源尺寸、解码尺寸和结果。
8. 真实解码失败时记录响应缓存驱逐及一次强制重取。
9. 最终交给封面或阅读器视图时记录 `display/success`。

取消是独立结果，不记作普通失败。日志必须指出取消发生在等待共享请求、网络、退避、解码或显示前的哪个阶段。

## 持久化与容量

- 内存中维护当前事件缓冲区，文件写入串行化。
- 最多保存最近 2,000 条事件。
- 超过上限时删除最旧事件，保留最新事件的原始顺序。
- 写入采用临时文件加原子替换，避免 App 中断后留下半个 JSON 文件。
- 启动时若日志文件损坏，将其移动为带时间戳的损坏备份并从空日志继续；图片加载不受影响。
- 日志写入、读取、轮转或清理失败只镜像到 OSLog，不向图片管线抛错。

## 导出格式

导出文件名：

`bika-image-diagnostics-YYYYMMDD-HHmmss.json`

顶层结构：

- `schemaVersion`；
- `exportedAt`；
- `app`：版本、构建号；
- `device`：设备型号、系统名称和系统版本；
- `settings`：当前图片质量，不包含账号设置；
- `summary`：事件总数、最早与最晚时间、按结果和用途统计；
- `events`：按 `sequence` 和时间排序的事件数组。

导出时先从存储组件取得不可变快照，再在临时目录生成文件。图片仍在加载时产生的新事件不会混入当前导出文件。

## 设置页交互

在设置页新增“图片诊断”区域：

- 显示当前日志条数；
- 显示最近一次图片错误时间，没有错误时显示“暂无错误”；
- “导出诊断日志”生成文件并打开系统分享面板；
- “清空诊断日志”经过二次确认后执行；
- 显示导出、清空或读取失败的简短状态消息。

日志默认常开，不提供开关。

用户开始导出前显示提示：导出文件包含完整图片 URL，只应发送给可信对象。取消分享不会删除导出文件对应的源日志。

## 隐私与安全

- 允许记录完整图片 URL，用户已明确确认。
- 禁止记录 Authorization、Cookie、同步 Token、密码和安全存储内容。
- 不记录图片正文、API JSON 正文或任意请求头集合。
- 错误描述经过规范化，只保留错误域、错误码和不包含响应正文的说明。
- 导出文件只在用户主动操作时生成并交给系统分享面板。
- 临时导出文件在下一次导出前或合理的生命周期清理，不长期积累。

## 错误处理

- 日志系统错误不影响图片请求、缓存、解码、预加载或显示。
- 导出失败时设置页显示本地化原因，原日志保持不变。
- 清空失败时继续显示原日志条数。
- 持久化文件损坏时保留损坏备份并自动恢复空存储。
- 缺少可选设备信息时使用 `unknown`，不阻止导出。

## 测试

### 单元测试

- 追加事件并保持顺序。
- 超过 2,000 条后只保留最新事件。
- 重新创建存储实例后可读取持久化事件。
- 损坏文件不会阻塞记录，并生成损坏备份。
- 同一实际请求的多个调用方具有不同 `requestID` 和相同 `networkRequestID`。
- 503、429、超时、HTML 错误页、截断图片、缓存驱逐、重试耗尽和取消产生预期时间线。
- 日志写入失败不改变图片加载返回值或错误。
- 导出 JSON 可解析、字段完整、顺序稳定。
- 导出快照不会包含快照之后追加的事件。
- 敏感字段和响应正文无法进入事件模型或导出文件。
- 清空日志后计数归零且持久化文件同步更新。

### ViewModel 与 UI 测试

- 设置页显示日志条数和最近错误时间。
- 导出成功时提供文件 URL，失败时显示错误消息。
- 清空需要确认，成功后刷新计数。
- 分享提示明确说明包含完整图片 URL。

### 回归验证

- 阅读器首帧 viewport 更新、中心点按工具栏、横向阅读保持不变。
- 竖向阅读仍按真实解码图片宽高比计算页面高度。
- 封面和阅读器仍共享图片数据与解码缓存。
- 图片请求取消和共享请求合并语义保持不变。

## 成功标准

- 复现空白图片后，无需重新编译或连接 Xcode，即可从设置页导出诊断文件。
- 单个失败图片可以通过完整 URL 和请求 ID 还原从调用、缓存、网络、解码到显示的路径。
- 可明确区分 HTTP 错误、非图片响应、截断数据、真实解码失败、任务取消和显示前丢弃。
- 日志最多保留 2,000 条，App 重启后仍存在。
- 日志和导出失败不影响阅读和封面加载。
- iOS 单元测试、图片管线测试和阅读器回归测试通过。
